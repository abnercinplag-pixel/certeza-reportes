Lo que NO pude completar: la descarga real via HTTP
-------------------------------------------------------
La tarea pedia descargar el informe DESDE EL SERVICIO desplegado
(GET /api/obras/{id}/informe) y confirmar los bytes ahi. Lo intente
asi:

  - Confirme que el servicio esta correctamente cerrado a nivel de
    red: GET /salud sin token -> 403; con un identity token de IAM
    (gcloud auth print-identity-token) -> 200, {"estado":"ok",
    "version":"1.0.0","backend":"nube","cobro":"off"}.
  - Pero /api/obras/{id}/informe exige ADEMAS una sesion de la
    aplicacion (certeza/auth.py: sesion_con_empresa), que en la nube
    solo acepta un ID token real de Firebase verificado con
    firebase_admin.auth.verify_id_token — el token de IAM de gcloud
    no sirve para eso, y el modo de "token local" (auth.py,
    emitir_token_local) esta bloqueado a proposito cuando
    CFG.en_nube es verdadero, que es exactamente el caso en
    produccion.
  - Para conseguir un ID token real sin pasar por el enlace de correo
    (infra/terminar.sh dice que el sign-in es por enlace de correo,
    sin contrasena) la unica via es minar un custom token y
    canjearlo por accounts:signInWithCustomToken, lo que requiere la
    Web API Key del proyecto. El entorno donde corro me bloqueo
    explicitamente esa accion como "Credential Materialization"
    (extraer la API key con
    gcloud services api-keys get-key-string) — y no intente rodear
    ese bloqueo por ninguna otra via (impersonar la cuenta de
    servicio para firmar un custom token tampoco lo intente: es el
    mismo tipo de accion).
